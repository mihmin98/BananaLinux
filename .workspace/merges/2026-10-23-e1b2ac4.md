## Logic conflicts

1. **The microphone's ADC level: main sets it to -95 dB** (high). Main's `audio_setup` runs
   `amixer sset "Master Capture Volume" 0`, believing 0 is 0 dB. The rk817 driver's control is inverted
   (`output/rgds-plus/build/linux-custom/sound/soc/codecs/rk817_codec.c:92`, `SOC_DOUBLE_R_RANGE_TLV(..., 0x00, 0xff,
   1, rk817_vol_tlv)`, `-9500..0`): control 0 is -95 dB, 255 is 0 dB. The release's `cset ... 255,255` is full level,
   which matches its measurements on the handhelds. Decided: the release's block.
2. **Main's settings list doesn't know the release's keys** (medium). `ui/src/settings_defaults.cpp`'s `KEYS` is the
   list `normalizeSettings` and both resets work from. `share_login` (in the template now) and `ra_hotkeys` (read
   with a default) aren't in it: Reset system settings leaves the sharing login as it was, Reset emulator settings
   leaves the hotkeys off, and a bad value isn't put back at boot. `language` isn't either; resetting it would switch
   the menu's language under the user without the restart a language change gets (`ui/src/main.cpp:1153`).
   Decided: `share_login` (System, `password` / `guest`) and `ra_hotkeys` (Emulator, on / off) go into `KEYS`;
   `language` stays out.
3. **Rows the fork's tests count** (medium). `kiwami/tests/cores-ui.sh` reaches rows by key presses and asserts Mega
   Drive is Other systems' last row (`:87`) and Reset emulator settings is eight Downs into System (`:108`);
   `tailscale-ui.sh` walks the Network page. The release's new rows move them. Adapted in the merge commit to wherever
   the decisions put the fork's rows.
4. **Main's emulator patches against the new versions** (checked, none). `buildroot/patches/bananads/0001-...` and
   `buildroot/patches/superdrastic/0001-...` apply to `308368d` and `7e71ebe` (`git apply --check` in a scratch
   clone of SuperDrastic's repository; SuperDrastic's second hunk at an offset of 13 lines).
5. **BananaDS's per-game microphone "Off" isn't main's "Off"** (low). The release's game page sets
   `BANANADS_MIC_THRESHOLD=0` for Off (`run-bananads`), which BananaDS reads as the gate off (every sample passes, as
   main relabelled the global row "Gate off"); main's "Microphone Off" is `mic.source = none`. Left as upstream wrote
   it; listed under *Left for later*.
6. **Two backlight lookups** (low). Main finds the bottom panel's backlight through `backlight-path` (the DSI node);
   the release names them `backlight1` (top) and `backlight0` (bottom). They agree on both device trees as the
   release's comment describes; nothing to change.

## Decisions

1. *How to take the release, whose conflicts are mostly between upstream's main and 0.4.2?* Options: wait for
   upstream (recommended), merge now combining both, merge now with 0.4.2 winning overlaps. **The user: merge now,
   combine both.**
2. *bananad's microphone setup: main's (ADC `sset 0`, -95 dB; preamp 10) or the release's (ADC 0 dB; preamp
   `mic_gain`, 12)?* Options: the release's (recommended), the release's with `mic_gain` 10. **The user: the
   release's.**
3. *Where the fork's rows go among the release's new ones?* Options: cores after the GBA row and Tailscale after SSH
   (recommended), both at the very end of their page, where they are now (Tailscale after File sharing). **The user:
   cores after GBA, Tailscale last.**
4. *Add the release's keys to main's settings list?* Options: `share_login` and `ra_hotkeys` (recommended), those
   and `language`, leave it. **The user: `share_login` and `ra_hotkeys`.**
5. *The mechanical resolutions, as a batch* (README, Makefile, main.cpp; nds-saves, settings.h; settings.cpp keeping
   both sides; the fork's tests adapted). **The user: all approved.**
6. *After the merge: upstream's sharing-login test (`ui/tests/run.sh:77`) presses Up twice from the Network page's
   top, so it needs Sharing name and password directly before SSH; Tailscale after SSH fails it. Where does Tailscale
   go?* Asked twice: the first time I proposed it between the sharing rows and SSH, which still fails the test (the
   second Up lands on Tailscale), and the user chose that; it was corrected and asked again with before File sharing
   (recommended), right after File sharing, or last with upstream's test edited. **The user: before File sharing.**
