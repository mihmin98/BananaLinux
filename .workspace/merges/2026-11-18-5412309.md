## Logic conflicts

1. **rcheevos linked twice into banana-ui** (high; the build fails). Upstream's rule now links `$(RC_OBJ)` (its
   rhash) and the fork's `kiwami.mk` compiles its own copy (`ui/src/kiwami/third_party/rcheevos`, `7f7f5bf`) into
   `SRC`: the same v12.5.0 files (`diff -r`: identical where both have them), 68 global symbols defined twice
   (`md5_*`, `rc_file_*`, `rc_hash_*`, compiled and compared with `nm`). No textual conflict: only the link shows it.
   The fork's copy can't simply be dropped either: `rahash.cpp` and `rachd.cpp` define `RC_HASH_NO_ENCRYPTED` and
   `RC_HASH_NO_ZIP`, which change `rc_hash_iterator_t`'s layout, and upstream builds without them. *Proposed*: the
   fork uses upstream's copy. `kiwami.mk` drops rcheevos from `KIWAMI_C` and from `KIWAMI_CFLAGS` (`-I`, the two
   defines); `rahash.cpp` and `rachd.cpp` include upstream's `rc_hash.h` without the defines (upstream's full rhash:
   the fork's code still unpacks `.zip`/`.7z` itself and hands rcheevos a buffer, so the zip hashing goes unused; the
   iterator is the fork's own, no global state, `rachd`'s reader per iterator as before); `kiwami/tests/ci.sh` links
   its unit test with upstream's objects; `ui/src/kiwami/third_party/rcheevos/` is deleted;
   `kiwami/DEPENDENCIES.md`'s row moves to the upstream table (upstream's pin, what the fork relies on). The fork
   doesn't need `rc_util.c`: upstream's build links the same `hash.c` without it.

2. **Upstream's Achievements page beside the fork's RetroAchievements group** (medium; two features overlap, nothing
   breaks). Upstream now has what the fork's investigation left out of scope ("a game's achievements from the
   library's game page", `.workspace/0019-retroachievements/investigation.md`) and a list from the game panel. The
   fork's group keeps what upstream doesn't have: sign in and out, remembered accounts, stats, the games on this card,
   `.7z` and `.chd` identification. Both show a game's list: the fork's from the games on this card (`ra-game.cpp`),
   upstream's from the game page and the panel. They share `accounts.conf`'s keys (the fork's sign-out empties them,
   so upstream's page then says there's no account) and the badges folder (`<data>/cache/ra-badges`, the same names,
   by design: `rastore.h:11`), and keep separate hash caches (`cache/ra` and `cache/ra-hashes`), so a game opened in
   both is hashed twice. *Proposed*: keep both in this merge; a separate change decides whether the fork's game list
   gives way to upstream's page (or opens it), and whether the caches are shared.

3. **The GBA flat-save fallback and the rework's `gba-seed`** (medium; upstream's fix would be lost, and its test
   fails). Upstream's `fc18e5e` adds `flat_gba_save` to the seed loops the rework moved into `gba-seed`, and its
