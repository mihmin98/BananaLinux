## Logic conflicts

1. **The fork's core rows and upstream's** (high). `3b46ce1` gives Other systems a row for each system with two or
   more installed cores, from `RA_SYSTEMS` (`ui/src/settings.cpp`, main `:417`), which already names Mesen for the
   NES and Genesis Plus GX for the Mega Drive, but not SameBoy; mGBA counts for the Game Boy and Game Boy Color. With
   the fork's cores in the image, the fork's `Kiwami::rows(O)` (`ui/src/kiwami/kiwami.cpp:65`) and upstream's loop
   would both add `core.nes` and `core.megadrive` rows, and `core.gb` / `core.gbc` twice with different choices.
   `run-retroarch` reads `core.<system>` as before (now also from the card's cores). `docs/FORK.md` (*Taking in
   upstream*, 3) foresaw this: "a row upstream adds for the NES, Game Boy, Game Boy Color or Mega Drive ... means the
   fork's rows have to follow". Decision 1.
2. **The game panel's RetroAchievements token** (medium). `aa2db2f` reads `ra_retroarch_token` from `accounts.conf`
   when `retroarch.cfg` has none and `ra_user` equals the panel's user, which is what the fork's hook
   (`ui/src/settings.cpp:3433`, `Kiwami::panelToken` → `kiwami::ra::panelToken`, `ui/src/kiwami/rastore.cpp:299`)
   does; the fork compares the names without case. Decision 2.
3. **The settings grid's seventh tile** (high). The fork's RetroAchievements group is a seventh tile (two rows shown,
   `kiwami::gridTop`). Upstream now adds sections after System that have no tile (Hotkeys, Power, Home server, Home
   server systems, Shown systems: `tileless()`), counts the tiles with `gridCount()` capped at 6, and navigates with
   `n = gridCount()`. Merged as it is, the RetroAchievements tile can't be reached (n is 6), and the fork's drawing and
   touch loops, which run to `groups.size()`, would draw Hotkeys and Power as tiles once the second row scrolls in.
   Proposed: the RetroAchievements hook placed before Hotkeys (textual hunk 7), one `kiwami:` line in `gridCount()`
   so it counts every tile while the fork's group is there, and the fork's four grid hook lines over `gridCount()`
   instead of `groups.size()`.
4. **Upstream's RetroArch changes the fork's master pin hides** (high: the build stops). The fork's patches replace
   upstream's (`kiwami/external.mk`), so upstream's new `0004` (the image's cores in RetroArch's lists, needed now that
   `libretro_directory` is the card's `/data/retroarch/cores`: without it RetroArch's Load Core and core information

   `kiwami/tests/retroarch-pin.sh`'s patch stamp fails `kiwami/tests/ci.sh`. Checked against master `71f521e`'s source
